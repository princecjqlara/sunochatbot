# Suno second audit — November 15, 2026

This audit covers the replacement in `sunobot/suno-system`. It does not establish production acceptance. The original Suno and Veo sources, live customer records, deployments, webhook and scheduler configuration were preserved.

## Coverage

The generated register classifies all 125 API routes, 22 pages, 56 principal components, 17 cron routes and 28 Python service paths into the 36 feature areas in the compatibility plan. Sixteen app cron schedules are declared; legacy sync is reserved for recovery. Both calendars, customer identity/profile/history, Page connections, teams, assignments, production, receipt review, reports, campaigns, exports and retention are represented. No route is unclassified.

Source coverage and local regression checks cannot confirm Suno's pay rules, historical job mapping or live permissions. Features awaiting those checks remain marked `compatibility_verified=false` in the coverage register.

## Corrections from the double-check

1. **Brief validation parity:** TypeScript and generated SQL now use the same placeholder patterns and Unicode key normalization. Canonical saved fields win over conflicting aliases; blank canonical values can use meaningful aliases. Duplicate aliases cannot count twice toward the song-domain detector or assignment threshold. The actual twenty-field profile and saved 26% threshold are retained.
2. **Human takeover recovery:** Page ownership scopes both lease recovery and due reviews. The final release and follow-up reservation use the service-only `suno_finish_takeover_review` transaction. A newer human message, changed policy/epoch/inbound anchor, held sale, trial restriction or foreign Page blocks release. Processing, acknowledged, failed and uncertain reserved deliveries cannot be reset by the review.
3. **Upgrade replay:** The planner reads both the original filename receipts and its own workspace receipts. Conflicting hashes fail closed, including conflicts between ledgers. Numeric migration prefixes are never used as file identity. Reconciliation checks stable row identities, column types and required not-null constraints.
4. **Cron authentication:** The five handlers that previously depended on middleware now authenticate before accessing data or invoking work. Direct-handler tests cover missing/wrong credentials, a forged middleware subrequest header and missing scheduler configuration. All seventeen routes retain middleware authorization too.
5. **Page ownership readiness:** The read-only setup diagnostic now explicitly checks `get_automation_page_scope`. A missing RPC, unenforced policy or empty ownership scope must be resolved before automation can launch; the feature flag must not be disabled to bypass this requirement.
6. **Dependency security:** The copied shared dependency junction was renamed without traversing or changing Veo's installation. Suno now has its own dependencies and lockfile, Next.js 15.5.29, NextAuth 4.24.15, matching Next lint configuration and Vitest 4.1.12. A PostCSS override selects the patched compatible 8.x implementation. Vercel installs with `npm ci`; Node 22 is declared. The production dependency audit reports zero findings. Six moderate development-only findings remain through the lint parser's minimatch dependency; a non-forced audit fix did not resolve them. No critical or high dependency finding remains in the full audit.
7. **Portable package:** The frozen budget-model fixture required by the regression suite is now included explicitly. Shared dependencies, local environments, private schema capture and build caches stay outside the source ZIP; configured private credentials are scanned before packaging.
8. **Regression tooling compatibility:** The modern runner uses an explicit Oxc automatic JSX transform and an ESM configuration. Test mock types use the current callable signature. Two offline SQL tests that build multiple full reports have explicit 30-second budgets; their data, access and privacy assertions remain intact. These corrections address issues found by the first audit-wide run.
9. **Old release entrypoint:** The inherited version-only release script now rejects preflight, apply and launch before creating a database connection, even if financial confirmation and archive acknowledgment are supplied. Review-only inspection remains available; use the Suno wrapper for the isolated rehearsal. This closes the direct entrypoint that could otherwise bypass the newer release wrapper.
10. **Deployment tracing boundary:** Next.js file tracing is explicitly rooted at this checkout. Parent-directory lockfiles cannot select another app or the Windows user directory as the Suno bundle's root.

The dependency choice follows the [Next.js support policy](https://nextjs.org/support-policy), which supports 15.x through January 31, 2027, and the [upstream SVG image security advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw), whose patched 15.x line starts at 15.5.28. Plan the Next.js 16 upgrade before maintenance support ends. Handler authorization also avoids depending entirely on the middleware boundary described in the [upstream middleware advisory](https://github.com/vercel/next.js/security/advisories/GHSA-f82v-jwr5-mffw).
