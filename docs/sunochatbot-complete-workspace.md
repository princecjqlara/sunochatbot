The release adds the Veo management workspace to the actual Sunochatbot project while retaining Suno's original chatbot implementation from commit 743ca57879e396e3c715ae5a2a59f2fa682fab6f.

The workspace includes role-based navigation, accounts and teams, Page assignments, contact profiles, intake and editor queues, readiness and availability, calendar and capacity, reviewed deals and receipt evidence, orders and payments, salary and incentives, budgets and ads reporting, Telegram integration, staff access and discipline, audit history, storage protection and background processing. The original chatbot settings screen, replies, knowledge, media, follow-ups and delivery implementation remain embedded and tested under `src/legacy-runtime`.

The live database installation applied 175 additive migrations. All 1,502 fields from the current Veo reference are present. During the locked transaction, all 120,597 original public-table rows, 443 original column contracts and 32 original function definitions were preserved. Enrollment retained the existing Owner identity and all 13 saved Page grants. Existing customers were retained in place; they were not turned into an automatic intake backlog. The private encrypted backup was restored and its exact upgrade rehearsed before production changes.

The new workspace uses separate versions of pre-existing RPCs. The retained chatbot continues using its original RPCs and model/Facebook credentials. The replacement Veo reply engine remains disabled. Contact bot-off controls integrate with the original human hold state and restore its prior state when re-enabled. Workspace event observation is deduplicated and cannot enqueue a second chatbot reply.

New financial writes and financial workers require the Owner to choose the displayed earnings rules. The current Veo policy is 40% for Managers; Members earn 40% when both personal Closed and Done targets are met and 35% otherwise. These rules have not been silently adopted for Suno. Existing customer history and bot settings do not require this choice.

The separate Danny Telegram deployment was found in setup mode with an empty dedicated archive, two configured Suno groups and no registered webhook. Telegram history, employees, sales and payments must come from verified Suno sources. Veo's business records and invented employees or transactions are not seeded into Suno. Telegram activation, verified staff identities and group-to-Page assignments remain operational prerequisites for those integrations.

Release verification includes the original Suno regression tests, workspace SQL and API tests, retained source checks and production compilation. Exact results and deployment status are recorded in `verification`; interrupted local runs are not reported as passing. Browser visual verification requires an available Browser connection.
